### 2026-09-14-a — Whisper Attacks + A-VIP (AP2 intent binding)

- **Kind:** paper
- **Date:** submitted **10 Sep 2026** (arXiv:2609.11757)
- **Link:** [Signing the Transaction but Not the Decision: Whisper Attacks and a Binding Defense for AP2](https://arxiv.org/abs/2609.11757)
- **Title:** Whisper Attacks / A-VIP — AP2 signs the cart, not the decision
- **Track:** sample-ready
- **Status:** queued

#### What it is

Agent Payments Protocol (AP2) signs intent, cart, and payment mandates so completed purchases verify cryptographically — but merchant-controlled product text can steer the shopping agent into a cart that still passes every protocol check while no longer matching the user’s request. The paper names three “whisper” attacks: (1) steer credential fetch toward another user’s payment method, (2) assemble a valid cart whose contents differ from what the user was shown, (3) factual stock/lineage claims that move the agent to a costlier SKU with no instruction-looking injection. Author-reported ASR on Gemini Flash-Lite sample agents: **90% / 56% / 73.3%**; same class of failure shown across many Google models and multiple agent frameworks. Defense **A-VIP** (AP2 Verified-Intent Protection) treats the signed intent as a **capability grant**: bind credential lookups to the requesting session, bind each cart line to the listing the user saw, flag unauthorized spend. Attacks 1–2 leave structural traces blocked at **0 false positives** in their eval; attack 3 needs user confirmation. Artifacts: A-VIP code, machine-checked invariants, **AP2-WhisperBench** (1,544 scenarios).

#### Why it is useful in the real world

Any MCP host/client or agent checkout path that trusts “the protocol verified the signature” while the merchant listing is untrusted content. Enterprise procurement bots, consumer shopping assistants, and payment MCP servers that expose `create_cart` / `charge` tools without binding cart lines to a user-visible listing ID.

#### Buildability

CPU weekend: mock AP2 mandates + a thin Python A-VIP binder that rejects cart lines whose `listing_hash` ≠ session-seen listing (no real payments). Full WhisperBench / multi-model sweep needs API keys and is heavier — keep the sample on the binding gate.

#### LinkedIn / demo

Strong: “signed cart, wrong product” — green check on crypto, red on intent binding. Public sample + one-pager fit.

#### Technical compare

- **Deadbugz / discovery sanitizer (queued/shipped):** defend MCP server *tool metadata* poisoning; Whisper is *merchant listing → payment decision* binding after tools already ran.
- **CapScope (queued):** capability scope on coding tools; A-VIP is **intent↔cart↔credential** binding for payments.
- **OpenAPPA (queued):** destination information-flow; A-VIP is protocol-mandate structural binding for AP2.
- **SEP-3140 / call-attestation samples:** pin tool menus / call labels; A-VIP pins *commerce intent* to cart lines.


### 2026-09-14-b — A2ABreak (A2A protocol FSM security analysis)

- **Kind:** paper
- **Date:** submitted **9 Sep 2026** (arXiv:2609.10871)
- **Link:** [A2ABreak: Systematic Security Analysis of the A2A Protocol](https://arxiv.org/abs/2609.10871)
- **Title:** A2ABreak — 11 spec-compliant vulns in Agent2Agent
- **Track:** watch
- **Status:** queued

#### What it is

First systematic security analysis of Linux Foundation **Agent2Agent (A2A)** — the horizontal agent↔agent layer designed to complement MCP’s vertical agent↔tool path. Method: LLM-assisted extraction of a verified finite-state machine from the natural-language spec (**37 states / 76 transitions** from **929** formalized statements), then adversarial verification **under full-compliance** (attacker needs no implementation bug). Reports **11 new vulnerabilities**, including cross-client context injection via unprotected context IDs, credential harvesting through multi-hop identity loss in delegation chains, and exfiltration via rogue agents advertising **unattested** capability claims. Authors report **73.3% precision / 84.6% F1** vs expert review; a zero-shot LLM baseline over the same spec produced **zero** confirmed findings — formal grounding mattered.

#### Why it is useful in the real world

Teams wiring MCP servers behind multi-agent orchestration that also speaks A2A for cross-org delegation. Security reviews that only harden MCP tool gates miss A2A’s discovery/auth/delegation surface. Useful threat-model checklist for “agent of agent” products.

#### Buildability

Watch this week for a LinkedIn *sample*: reproducing the full FSM extraction is research-scale. Thin sample path later: one A2A-shaped context-ID isolation check or unattested capability claim rejector — cite the paper, don’t claim the full 11.

#### LinkedIn / demo

Skip full repro for now; short explainer carousel (“MCP ≠ A2A trust”) is fine without code. Sample when you pick one concrete vuln to fence.

#### Technical compare

- **MCP-to-A2A egress paper (queued):** focuses on public-sharing egress; A2ABreak is **spec-wide FSM** vuln discovery under compliance.
- **ATSA / SEP-2809 (shipped sample):** MCP server admission attestation; A2ABreak shows **A2A capability ads** without attestation.
- **Delegation Without Trust (queued):** conceptual delegation broker; A2ABreak is empirical protocol analysis with a machine model.
- **Zero-shot LLM audit of specs:** paper’s own ablation — without the FSM, findings collapse.


### 2026-09-14-c — OpenTrustBench (OWASP Trust Cards for agents/MCP)

- **Kind:** tool / recent implementation
- **Date:** v0.1.3 **10 Sep 2026**; active pushes through **14 Sep 2026** (registry refresh, design/theme)
- **Link:** [eulogik/OpenTrustBench](https://github.com/eulogik/OpenTrustBench)
- **Title:** OpenTrustBench — local Trust Card (A–F) + SARIF for agents/MCP servers
- **Language / license:** TypeScript (+ thin Python wrapper); **Apache-2.0**
- **Stars:** **7** at briefing time (early momentum; substance + daily commits — not the monthly mega-repo)
- **Track:** sample-ready
- **Status:** queued

#### What it is

Local-first scanner for AI agents and MCP servers: **8** regex/static rules mapped to OWASP Agentic ASI01–ASI10 and LLM Top 10 2025, emitting a machine-readable **Trust Card** (`opentrustbench/trust-card/v1`), SARIF, markdown report, and shareable A–F badge. CLI via `npx @opentrustbench/cli scan …`, plus GitHub Action, Docker, Homebrew, VS Code extension. Authors are explicit about limits: no AST yet; `attack` is static-heuristic (no live payloads); `eval` is simulation; Trust Card ≠ certification. Zero telemetry claim; weekly registry refresh observed on 2026-09-14.

#### Why it is useful in the real world

Procurement / platform teams that want a **CI gate + README badge** before allowing an MCP server into a host catalog — lighter than a full red-team platform, faster than waiting on SkillSpector-class depth. Pair with discovery sanitizer (runtime/description) and OpenTrustBench (install-time static grade).

### 2026-09-14-d — NVIDIA SkillSpector (agent-skill security scanner)

- **Kind:** tool / monthly-trending
- **Date:** public OSS line active; notable commits **12 Sep 2026** (analyzer/manifest); README cites NVIDIA Verified Skills pipeline

- **Track:** sample-ready
- **Status:** queued

#### What it is

Pre-install security scanner for AI agent skills (and related MCP config surfaces). Claims **71** vulnerability patterns across **17** categories (prompt injection, exfil, privilege escalation, supply chain, MCP least privilege, MCP tool poisoning, YARA, AST dangerous-code, taint, etc.). Two-stage analysis: fast static + optional LLM semantic pass; OSV live CVE lookups with offline fallback; outputs terminal/JSON/Markdown/SARIF; risk score 0–100; baseline/suppression for known findings. Can run as CLI, Docker (`--no-llm`), or `skillspector mcp` for in-session scans. Part of NVIDIA’s scan→evaluate→sign skills catalog flow.

#### Why it is useful in the real world

Enterprises letting developers drop third-party `SKILL.md` / agent-skill packs into Cursor/Claude/Codex — same supply-chain moment as npm, but with prompt-injection and tool-poisoning baked in. MCP host/client install gates that already sanitize discovery can add SkillSpector (or a thin rule subset) as the **skill pack** checker.
